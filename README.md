# creator-studio

### AI 챗봇 및 이미지 창작자를 위한 로컬 기반 통합 제작 워크스페이스

**Creator Studio**는 AI 챗봇 제작과 이미지 창작 과정에서 반복되는 작업을 하나의 데스크톱 애플리케이션으로 통합하기 위한 개인 개발 프로젝트입니다.

프롬프트 작성부터 이미지 후처리, 에셋 관리, 캔버스 편집, HTML 출력까지 이어지는 제작 과정을 보다 효율적이고 직관적으로 만드는 것을 목표로 합니다.

> **개발 상태:** 초기 개발 단계  
> **프로젝트 유형:** 개인 프로젝트 / 프론트엔드 학습 및 포트폴리오  
> **주요 환경:** Windows 데스크톱  
> **기본 UI 언어:** 한국어

---

## 1. 프로젝트를 시작한 이유

AI 챗봇을 제작하면서 하나의 작품에 수십 장에서 수백 장의 이미지를 사용하게 되는 경우가 있습니다.

이미지 생성뿐 아니라 배경 제거, 검열, 메타데이터 제거, 파일 정리, HTML 에셋 제작 등 다양한 작업이 필요합니다.

그러나 이러한 작업을 처리하기 위해 여러 프로그램과 웹 서비스를 반복적으로 이동해야 하는 불편함이 있었습니다.

특히 기존 도구를 사용하면서 다음과 같은 문제를 경험했습니다.

- **배경 제거:** 자동 처리 과정에서 캐릭터의 머리카락이나 의상 등 필요한 이미지 영역까지 제거되는 문제
- **이미지 후처리:** 검열 및 메타데이터 제거를 위해 서로 다른 도구를 사용해야 하는 번거로움
- **에셋 제작:** 이미지와 텍스트를 조합한 결과물을 챗봇 플랫폼용 HTML로 변환하는 과정의 복잡함
- **대량 이미지 관리:** 작품별로 수많은 이미지 파일을 반복적으로 정리하고 변환하는 작업

이러한 문제를 해결하기 위해 Creator Studio를 기획했습니다.

단순한 이미지 편집기가 아니라 **창작자의 실제 제작 흐름을 하나로 연결하는 도구**를 만드는 것이 프로젝트의 출발점입니다.

## 2. 핵심 목표

Creator Studio가 지향하는 제작 흐름은 다음과 같습니다.

**이미지 생성형 AI 프롬프트 제작 → 이미지 준비 → 이미지 후처리 → 에셋 관리 → 캔버스 편집 → HTML / 이미지 출력**

### 주요 개발 원칙

- **Local First:** 이미지 처리와 프로젝트 관리를 가능한 한 로컬 환경에서 수행합니다.
- **원본 보호:** 이미지 원본을 기본적으로 덮어쓰지 않고, 미리보기와 결과물 내보내기를 분리합니다.
- **작업 통합:** 여러 프로그램에서 반복적으로 수행하던 작업을 하나의 워크스페이스로 연결합니다.
- **대량 작업 지원:** 수십~수백 장의 에셋을 효율적으로 관리하고 처리할 수 있도록 설계합니다.
- **확장 가능한 구조:** AI 모델과 이미지 처리 엔진을 필요에 따라 교체할 수 있도록 설계합니다.

## 3. 주요 기능

아래 기능은 전체 프로젝트의 개발 목표이며, 단계적으로 구현할 예정입니다.

| 기능 | 설명 |
|---|---|
| 프롬프트 스튜디오 | 자연어를 이미지 생성용 태그로 변환하고 프롬프트를 편집 |
| 프롬프트 태그 편집기 | 태그 추가·삭제, 순서 변경, 가중치 조절, 프리셋 관리 |
| AI 배경 제거 | 이미지 배경을 제거하고 마스크를 이용해 세밀하게 보정 |
| AI 자동 검열 | 특정 노출 영역을 탐지하고 지정된 검열 방식 적용 |
| 이미지 정보 제거 | EXIF, XMP, 생성 프롬프트 등 메타데이터 제거 |
| 캔버스 편집기 | 이미지, 텍스트, 도형을 자유롭게 배치하고 편집 |
| HTML 에셋 생성 | 캔버스에 배치된 요소를 인라인 HTML 등으로 변환 |
| 일괄 처리 | 이미지 변환, 이름 변경, 후처리 등을 여러 파일에 적용 |
| 프로젝트 관리 | 작업 중인 에셋과 편집 상태를 저장하고 복원 |

### AI 기능의 적용 방향

모든 기능을 AI에 의존하도록 개발하지 않습니다.
일반적인 코드로 정확하게 처리할 수 있는 기능은 규칙 기반으로 구현하고, 이미지 인식이나 자연어 변환 등 AI가 실질적인 가치를 제공하는 기능에 선택적으로 적용할 예정입니다.

### 외부 AI API 연동 및 보안

**사용자가 개인 API 키를 등록하여 원하는 AI 서비스를 연동할 수 있도록 설계할 예정입니다.**
개발 환경에서는 환경변수를 활용하고, 실제 사용자 환경에서는 운영체제의 보안 저장소 또는 암호화된 저장 방식을 검토합니다.

API 키는 소스 코드에 하드코딩하거나 Git 저장소에 포함하지 않습니다.
민감한 정보가 프론트엔드 번들, 로그 및 프로젝트 내보내기 파일에 노출되지 않도록 설계합니다.
외부 API로 이미지 및 데이터를 전송하는 경우 전송 대상과 내용을 사용자에게 명시합니다.
외부 API 없이도 핵심 로컬 기능을 사용할 수 있도록 개발합니다.

## 4. 기술 스택

현재 계획 중인 기술 구성입니다. 개발 과정에서 기술적 필요성에 따라 변경될 수 있습니다.

| 영역 | 기술 |
|---|---|
| Desktop | Tauri |
| Frontend | React, TypeScript, Vite |
| Styling | CSS Modules |
| State Management | React Hooks, Zustand(예정) |
| Canvas | Konva.js(우선 검토) |
| Local Database | SQLite(예정) |
| Image Processing | Python, Pillow, OpenCV |
| AI Inference | PyTorch, Local AI Models |
| AI Integration | Local LLM / External API Provider |

### 기본 아키텍처

**React + TypeScript → Tauri → Local Service / Python Worker → 이미지 처리 및 AI 추론**

프론트엔드는 사용자 인터페이스와 상호작용, 편집 상태 관리를 담당합니다.

이미지 처리와 AI 모델 추론은 별도 서비스 또는 Worker로 분리하여 UI의 응답성을 유지하는 구조를 목표로 합니다.

## 5. 개발 로드맵

### Phase 1 — 프론트엔드 기반 및 MVP

프로젝트의 핵심 사용자 흐름을 완성하는 단계입니다.

- [ ] React + TypeScript + Tauri 프로젝트 구성
- [ ] 데스크톱 워크스페이스 및 기본 UI 구현
- [ ] 프롬프트 태그 편집기
- [ ] 이미지 불러오기 및 에셋 관리
- [ ] 캔버스 기본 편집 기능
- [ ] 캔버스 기반 인라인 HTML 출력
- [ ] 프로젝트 저장 및 불러오기

**첫 번째 목표:** 프롬프트 작성부터 이미지 배치, HTML 에셋 출력까지 실제로 사용할 수 있는 제작 흐름 완성

### Phase 2 — 이미지 후처리

- [ ] 이미지 메타데이터 확인 및 제거
- [ ] 이미지 형식 변환 및 재인코딩
- [ ] AI 기반 배경 제거
- [ ] 마스크 미리보기 및 수동 보정
- [ ] 기본 이미지 일괄 처리

### Phase 3 — AI 기반 자동화

- [ ] 자연어 기반 프롬프트 자동 생성
- [ ] 이미지 특정 영역 자동 탐지
- [ ] 자동 검열 및 수동 보정
- [ ] 정밀 Segmentation 처리
- [ ] AI 보조 HTML 코드 개선

### Phase 4 — 고급 편집 및 최적화

- [ ] 캔버스 레이어·그룹·정렬 기능 확장
- [ ] Undo / Redo 및 작업 복구 기능
- [ ] 대량 이미지 처리 최적화
- [ ] AI 모델 및 Provider 관리
- [ ] 사용자별 내보내기 프리셋

※ 개발 일정과 세부 우선순위는 실제 구현 난이도 및 테스트 결과에 따라 조정될 수 있습니다.

## 6. 프로젝트 설계 원칙

### 원본과 결과물 분리

이미지 편집은 원본 데이터를 유지하면서 처리 결과를 미리 보여준 뒤, 사용자가 명시적으로 내보내도록 설계합니다.

### 데이터 중심 캔버스

캔버스에 표시된 객체를 단순한 화면 요소로만 관리하지 않고, 좌표와 크기, 레이어 순서 등을 포함한 Scene Graph 데이터로 관리합니다.

이를 기반으로 저장·복원 및 HTML 변환 기능을 구현할 계획입니다.

### 예측 가능한 HTML 생성

캔버스에서 HTML을 생성할 때 기본적인 레이아웃 변환은 규칙 기반으로 처리합니다.

LLM은 필요한 경우 코드 정리, 구조 개선, 사용자 요청에 따른 스타일 수정 등을 보조하도록 설계합니다.

### 기능별 모듈 분리

프롬프트 편집, 이미지 처리, 캔버스 및 내보내기 기능을 독립적인 모듈로 구성해 유지보수와 기능 확장이 가능하도록 합니다.

## 9. 프로젝트의 최종 목표

**Creator Studio의 목표는 가능한 한 많은 기능을 구현하는 것이 아닙니다.**

창작자가 실제로 겪는 불편함을 해결하고, 반복적인 제작 작업을 줄이며, 하나의 프로그램 안에서 효율적인 창작 환경을 제공하는 것입니다.
작은 기능부터 실제로 작동하는 형태로 완성하고, 이를 점진적으로 연결해 하나의 제작 워크스페이스로 발전시키는 것을 목표로 합니다.
